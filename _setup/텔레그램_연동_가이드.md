# 견적 요청 → 텔레그램 알림 연결

고객이 사이트에서 **구매 요청 보내기**를 누르면 텔레그램으로 알림이 오게 만드는 설정입니다. 15분 정도 걸립니다.

## 왜 중계가 필요한가

텔레그램 봇 토큰을 사이트 코드(`products.js`)에 바로 넣으면, 공개 저장소라서 누구나 토큰을 보고 봇을 마음대로 쓸 수 있습니다. 그래서 토큰은 **Google Apps Script**(무료, 구글 계정만 있으면 됨)에 숨겨 두고, 사이트는 그 주소로만 요청을 보냅니다.

```
고객 브라우저 → Apps Script (토큰 보관) → 텔레그램 봇 → 담당자 텔레그램
```

---

## 1. 텔레그램 봇 만들기

1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 입력
3. 봇 이름 입력 (예: `클라우드에어 견적 알림`)
4. 봇 아이디 입력 — `bot`으로 끝나야 함 (예: `cloudair_quote_bot`)
5. 받은 **토큰**을 복사해 둡니다 — `1234567890:AAH...` 형태

토큰은 비밀번호와 같습니다. 채팅방이나 저장소에 올리지 마세요.

## 2. 알림 받을 채팅 ID 확인

**혼자 받을 때**

1. 방금 만든 봇을 검색해 대화방을 열고 아무 메시지나 보냅니다 (예: `안녕`)
2. 브라우저 주소창에 아래를 입력 (`<토큰>` 자리에 1번에서 받은 토큰)

   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```

3. 나오는 글에서 `"chat":{"id":123456789` 의 **숫자**가 채팅 ID입니다

**팀 단톡방에서 같이 받을 때**

1. 텔레그램 그룹에 봇을 초대하고 그룹에서 아무 메시지나 보냅니다
2. 위와 같은 주소로 확인 — 그룹 ID는 `-100...` 처럼 **마이너스로 시작**합니다. 마이너스까지 전부 복사하세요

`getUpdates` 결과가 `"result":[]`로 비어 있으면, 봇에게 메시지를 한 번 더 보낸 뒤 새로고침하세요.

## 3. Apps Script 만들기

1. **script.google.com** 접속 (회사 구글 계정으로 로그인) → **새 프로젝트**
2. 제목을 `견적기 텔레그램 중계`로 바꾸기
3. 기본 코드를 전부 지우고, 이 폴더의 **`Code.gs`** 내용을 통째로 붙여넣기 → 저장

## 4. 토큰과 채팅 ID 저장

1. 왼쪽 **톱니바퀴(프로젝트 설정)** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가**
2. 두 개를 추가하고 **저장**

   | 속성 | 값 |
   | --- | --- |
   | `BOT_TOKEN` | 1번에서 받은 토큰 |
   | `CHAT_ID` | 2번에서 확인한 숫자 |

## 5. 연결 테스트

1. 왼쪽 **편집기(`<>`)**로 돌아가서, 위쪽 함수 선택 칸에서 **`testSend`** 선택 → **실행**
2. 처음 실행하면 권한 확인 창이 뜹니다
   - **권한 검토** → 구글 계정 선택
   - "Google에서 확인하지 않은 앱" 화면이 나오면 **고급** → **(안전하지 않음)으로 이동** → **허용**
   - 본인이 만든 스크립트라 뜨는 정상 절차입니다
3. 텔레그램에 `[테스트] 견적기 텔레그램 연결이 정상입니다.`가 오면 성공

안 오면 실행 로그를 보세요. "전송 실패"면 토큰이나 채팅 ID가 틀린 것입니다.

## 6. 웹 앱으로 배포

1. 오른쪽 위 **배포** → **새 배포**
2. 유형 선택 톱니바퀴 → **웹 앱**
3. 설정
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** → 나오는 **웹 앱 URL** 복사 — `https://script.google.com/macros/s/.../exec` 형태

## 7. 사이트에 연결

`products.js` 맨 위쪽의 이 줄에 6번 URL을 붙여넣습니다.

```js
telegramRelayUrl: "https://script.google.com/macros/s/.../exec",
```

그다음 평소처럼 올리면 끝입니다.

```powershell
git add .
git commit -m "텔레그램 알림 연결"
git push
```

## 8. 실제 요청 테스트

1~2분 뒤 사이트에서 서비스를 하나 담고, 이름·소속·이메일을 넣고 **구매 요청 보내기** → 텔레그램에 이런 메시지가 오면 완료입니다.

```
[AI 구독 견적 요청] 2026-09-29 18:30

OO대학교 홍길동
이메일 name@example.ac.kr

1. ChatGPT Plus · 2계정 · 12개월
2. Claude Pro · 1계정 · 6개월
```

## 알아두실 점

- **URL이 설정되기 전**에는 고객이 보내기를 누르면 "지금은 온라인 요청을 받을 수 없습니다. 이메일로 연락 주세요"라고 안내됩니다.
- `Code.gs`를 고쳤다면 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 해야 반영됩니다. 이렇게 하면 URL은 그대로 유지됩니다. "새 배포"를 다시 누르면 URL이 바뀌니 주의하세요.
- 10분에 30건이 넘으면 잠시 요청을 막습니다. 사람 확인(아래 9번)을 켜면 확인을 통과한 요청만 세기 때문에, 가짜 요청 때문에 진짜 고객이 막히는 일은 없어집니다. `Code.gs` 맨 위 `MAX_PER_10MIN` 숫자로 조절할 수 있습니다.
- 봇 토큰이 노출됐다고 생각되면 @BotFather에서 `/revoke`로 토큰을 새로 받고, 스크립트 속성의 `BOT_TOKEN`만 바꾸면 됩니다.

## 9. 사람 확인 켜기 (Cloudflare Turnstile)

중계 주소(웹 앱 URL)는 사이트 코드에 보이기 때문에 누구나 알 수 있습니다. 사람 확인을 켜면 **우리 사이트에서 확인을 통과한 요청만** 텔레그램으로 넘어갑니다. 확인 토큰은 우리 사이트 주소에서만 발급되고, 한 번 쓰면 끝이며 5분 뒤 만료됩니다.

### 9-1. 키 받기

1. **dash.cloudflare.com** 가입·로그인 (무료)
2. 왼쪽 메뉴 **Turnstile** → **Add widget**
3. 설정
   - Widget name: `견적기`
   - Hostname: `cloudairac01-arch.github.io`
   - Widget Mode: **Managed** (대부분 자동 통과, 의심될 때만 체크)
4. 만들면 나오는 두 값을 복사
   - **Site Key** — 공개해도 되는 값
   - **Secret Key** — 비밀 값, 절대 사이트에 넣지 마세요

### 9-2. 중계에 비밀 키 넣기

Apps Script → 프로젝트 설정 → 스크립트 속성 → 추가

| 속성 | 값 |
| --- | --- |
| `TURNSTILE_SECRET` | Secret Key |

넣는 순간부터 사람 확인 없는 요청은 거절됩니다. 그러니 **9-3을 바로 이어서** 해 주세요.

### 9-3. 사이트에 사이트 키 넣기

`products.js` 맨 위쪽:

```js
turnstileSiteKey: "0x4AAAA...",   // Site Key
```

push 하면 보내기 버튼 위에 확인 상자가 나타납니다.

순서를 거꾸로(사이트 키 먼저) 해도 문제는 없습니다. 비밀 키를 넣기 전까지는 중계가 확인 결과를 보지 않기 때문입니다.

### 회사 도메인을 붙였다면

`quote.cloud-air.kr` 처럼 주소가 바뀌면 두 군데에 추가하세요.

- Cloudflare Turnstile 위젯의 Hostname 목록
- 스크립트 속성 `ALLOWED_HOSTS` = `cloudairac01-arch.github.io,quote.cloud-air.kr`

## 10. 중계가 검사하는 것

| 순서 | 검사 | 걸리면 |
| --- | --- | --- |
| 1 | 봇이 채우는 숨김 칸 | 조용히 무시 (봇은 성공한 줄 앎) |
| 2 | 성명 40자·소속 60자 이내, 링크 금지 / 이메일 형식 / 연락처는 숫자·-·+·()만 / 상품 1~20개, 계정 1~99, 개월 1~36, 중복 없음 | 입력 확인 안내 |
| 3 | 사람 확인 토큰이 진짜이고 우리 사이트에서 발급됐는지 (비밀 키를 넣은 뒤부터) | 다시 확인 안내 |
| 4 | 사이트 `products.js`에 **판매중·선행조건**으로 올라 있는 상품·플랜인지 | 입력 확인 안내 |
| 5 | 10분 30건 (위 검사를 모두 통과한 요청만 셈) | 잠시 후 안내 |

**상품 목록 대조**: 중계는 사이트의 `products.js`를 읽어 1시간 동안 기억합니다. 목록에 없는 상품이 오면 한 번 새로 읽어서 다시 확인하므로, 새 상품을 올린 뒤에도 따로 할 일은 없습니다. 다만 GitHub Pages 반영(1~2분)과, 같은 5분 안에 이미 새로 읽은 적이 있으면 그 시간만큼 늦게 통과될 수 있습니다.

편집기에서 **`testCatalog`** 를 실행하면 중계가 읽은 상품 목록이 로그에 나옵니다.

## `Code.gs`를 새 버전으로 바꿀 때

1. Apps Script 편집기에서 기존 코드를 전부 지우고 새 `Code.gs`를 붙여넣기 → 저장
2. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**
3. URL은 그대로라 `products.js`는 고칠 필요 없습니다
